# Ручная загрузка данных реимбурсации

Перед запуском workflow `Update reimbursement database` (`workflow_dispatch`) поместите в эту папку **ровно один** официальный XLSX-файл реимбурсации. Workflow никогда не скачивает исходный файл автоматически — он использует только файл, добавленный сюда.

## Требования к файлу

- Расширение `.xlsx` без учёта регистра. В папке должен находиться ровно один такой файл: отсутствие файла или наличие двух и более файлов приведёт к ошибке сборки.
- В первых 20 строках первого листа workbook должна присутствовать дата реестра в формате `станом на <дата>`. Дата базы определяется именно из этого текста, поэтому файл без неё будет отклонён.
- Первый лист должен содержать ожидаемые колонки реимбурсации и все три раздела:
  `I. Лікарські засоби…`, `II. Препарати інсуліну`, `III. Комбіновані лікарські засоби`.

## Что делает сборка

1. Скачивает предыдущий GitHub Release **только как baseline** — он никогда не используется как источник новых данных.
2. Пересобирает `reimbursement_items` из XLSX и переносит остальные данные из baseline (`reference_price_items`, `reimbursement_medical_devices`, VIEW и curated `icd10_codes`).
3. Проверяет объём данных, сохранность ICD-10, целостность SQLite, содержимое ZIP и контрольную сумму.
4. Загружает `reimbursement.sqlite`, `reimbursement.zip`, `reimbursement_manifest.json` и `build_summary.json` как artifacts workflow.

**GitHub Release автоматически не создаётся.** Публикация выполняется вручную. Используйте тег, указанный как `expected_release_tag` в `build_summary.json`. Если использовать другой тег, `downloadURL` внутри manifest не совпадёт с release, и iOS-клиент не сможет скачать обновление.

## Дополнительные разрешения

Все параметры по умолчанию выключены и должны включаться вручную во входных параметрах workflow:

- `allow_pipeline_transition` — предыдущий release был создан другим pipeline или из другого источника (например, PDF-based `reimbursement-v4`). Проверка объёма всё равно выполняется относительно фактических данных предыдущей базы.
- `allow_same_source_date` — разрешает повторную сборку workbook с датой реестра, которая не новее опубликованной (например, исправленный файл за ту же дату).
- `allow_missing_baseline` — используется только если предыдущего release действительно ещё не существует. Не используйте этот параметр для обхода ошибки загрузки baseline.
